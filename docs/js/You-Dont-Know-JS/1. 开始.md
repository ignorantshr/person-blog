## 类型

值有两种类型：原始类型和对象。
除了字符串、数字和布尔值，JS程序中还有另外两个*原始*值是`null`和`undefined`。
数组是一种特殊类型的对象。
函数，像数组一样，是对象的一种特殊类型（又名子类型）。

```js
typeof 42;                  // "number"
typeof "abc";               // "string"
typeof true;                // "boolean"
typeof undefined;           // "undefined"
typeof null;                // "object" -- 哎呀，bug！
typeof { "a": 1 };          // "object"
typeof [1,2,3];             // "object"
typeof function hello(){};  // "function"
```

用`const`与对象值一起使用是不明智的，因为即使变量不能被重新赋值，这些值仍然可以被改变。

由于函数是值，它们可以作为属性赋给对象：

```js
var whatToSay = {
    greeting() {
        console.log("Hello!");
    },
    question() {
        console.log("What's your name?");
    },
    answer() {
        console.log("My name is Kyle.");
    }
};

whatToSay.greeting();
// Hello!
```

在许多语言中，开发者可以选择将值本身赋值/传递，或者作为值的引用。然而，在JS中，这个决定完全由值的类型决定。

- 原始类型的值总是作为**值副本**进行赋值/传递。
- 只有对象值（数组、对象、函数等）被视为引用，在赋值/传递时复制的是引用。

原始类型按值持有，对象按引用持有。

## 比较

**所有**JS中的值比较都考虑被比较值的类型，*不仅仅是*`===`运算符。具体来说，`===`在其比较中不允许任何类型的转换（即“强制转换”），而其他JS比较*确实*允许强制转换。
`===`运算符两种特殊情况：

```js
NaN === NaN;            // false，使用`Number.isNaN(..)`
0 === -0;               // true
```
**在JS中，所有对象值都通过引用持有，通过引用复制进行赋值和传递**，**并且**，在我们当前的讨论中，**通过引用（身份）相等进行比较**。

但是`==`允许*首先*进行类型转换，一旦类型被转换为两边都相同，那么`==`做的就和`===`一样了。只要意识到`==`的这个特性——它**偏爱原始数字比较**——就能帮助你避免大多数麻烦的边缘情况。因此`==`导致非数字值（`"42"`和`true`）在进行比较之前被转换为数字。像`<`、`>`（甚至`<=`和`>=`）这样的关系比较运算符，与`==`一样。

```js
undefined == null;		// true
undefined === null;		// false
```

你可以把`Object.is(..)`看作是“四等号”`====`，即**真正**严格的比较！

[Object.is()](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Object/is) 确定两个值是否为[相同值](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide/Equality_comparisons_and_sameness#使用_object.is_进行同值相等比较)。如果以下其中一项成立，则两个值相同：

- 都是 [`undefined`](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/undefined)
- 都是 [`null`](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Operators/null)
- 都是 `true` 或者都是 `false`
- 都是长度相同、字符相同、顺序相同的字符串
- 都是相同的对象（意味着两个值都引用了内存中的同一对象）
- 都是 [BigInt](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/BigInt) 且具有相同的数值
- 都是 [symbol](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Symbol) 且引用相同的 symbol 值
- 都是数字且
    - 都是 `+0`
    - 都是 `-0`
    - 都是 [`NaN`](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/NaN)
    - 都有相同的值，非零且都不是 [`NaN`](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/NaN)

`Object.is()` 与 [`==`](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Operators/Equality) 运算符并不等价。`==` 运算符在测试相等性之前，会对两个操作数进行类型转换（如果它们不是相同的类型），这可能会导致一些非预期的行为，例如 `"" == false` 的结果是 `true`，但是 `Object.is()` 不会对其操作数进行类型转换。

`Object.is()` 也*不*等价于 [`===`](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Operators/Strict_equality) 运算符。`Object.is()` 和 `===` 之间的唯一区别在于它们处理带符号的 0 和 `NaN` 值的时候。`===` 运算符（和 `==` 运算符）将数值 `-0` 和 `+0` 视为相等，但是会将 [`NaN`](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/NaN) 视为彼此不相等。

### 布尔值
JavaScript中“假”值的具体列表如下：

- `""` (empty string)""（空字符串）
- `0`, `-0`, `0n`, `NaN` (invalid number)
- `null`, `undefined`
- `false`

任何不在这个“假”列表中的数值都是“真”的。

## 模块

*经典模块*的关键特征是一个外部函数（至少运行一次），它返回一个模块的“实例”，该实例公开一个或多个可以操作模块实例内部（隐藏）数据的函数。

```js
function Publication(title,author,pubDate) {
    var publicAPI = {
        print() {
            console.log(`
                Title: ${ title }
                By: ${ author }
                ${ pubDate }
            `);
        }
    };

    return publicAPI;
}

function BlogPost(title,author,pubDate,URL) {
    var pub = Publication(title,author,pubDate);

    var publicAPI = {
        print() {
            pub.print();
            console.log(URL);
        }
    };

    return publicAPI;
}

var forAgainstLet = BlogPost(
    "For and against let",
    "Kyle Simpson",
    "October 27, 2014",
    "https://davidwalsh.name/for-and-against-let"
);

forAgainstLet.print();
```

继承的和被覆盖的方法可以有相同的名称并共存，这一事实被称为*多态*。
ESM实际上是“单例”，因为在你的程序中第一次`import`时只创建一个实例，所有其他`import`都只接收对该单个实例的引用。如果你的模块需要支持多个实例化，你必须为此目的在你的ESM定义上提供一个*经典模块风格的*工厂函数。

## 迭代

ES6直接在语言中标准化了一个特定的迭代器模式协议。该协议定义了一个`next()`方法，其返回值是一个名为*迭代器结果*的对象；该对象具有`value`和`done`属性，其中`done`是一个布尔值，在对底层数据源的迭代完成之前为`false`。
ES6还包括了几种机制（语法和API）来标准化消费这些迭代器。

一种这样的机制是`for..of`循环。

```js
var a = ["a", 1]
for (let e of a) {
    console.log(e)
}

a
1
```

另一种常用于消费迭代器的机制是`...`运算符，其*展开*形式是一个迭代器消费者。

ES6将JS中的基本数据结构/集合类型定义为可迭代对象。这包括字符串、数组、映射、集合等。

```js
// 给定两个DOM元素，`btn1`和`btn2`

var buttonNames = new Map();
buttonNames.set(btn1,"Button 1");
buttonNames.set(btn2,"Button 2");

for (let [btn,btnName] of buttonNames) {
    btn.addEventListener("click",function onClick(){
        console.log(`Clicked ${ btnName }`);
    });
}

for (let btnName of buttonNames.values()) {
    console.log(btnName);
}

var arr = [ 10, 20, 30 ];

for (let [idx,val] of arr.entries()) {
    console.log(`[${ idx }]: ${ val }`);
}
```

## 闭包

```js
for (let [idx,btn] of buttons.entries()) {
    btn.addEventListener("click",function onClick(){
       console.log(`Clicked on button (${ idx })!`);
    });
}
```

因为这个循环使用了`let`声明，所以每次迭代都会得到新的块级作用域（即局部）的`idx`和`btn`变量；循环每次也会创建一个新的内部`onClick(..)`函数。该内部函数闭包了`idx`，只要点击处理程序设置在`btn`上，它就会保留它。所以当每个按钮被点击时，它的处理程序可以打印其相关的索引值，因为处理程序记住了它各自的`idx`变量。

记住：这个闭包不是针对值（比如`1`或`3`），而是针对变量`idx`本身。

## `this` 关键字

当一个函数被定义时，它通过闭包*附加*到其封闭作用域。作用域是控制如何解析变量引用的一组规则。

但是函数除了其作用域之外，还有另一个影响其可以访问内容的特性。这个特性最好被描述为一个*执行上下文*，它通过其`this`关键字暴露给函数。函数的执行*上下文*是动态的，完全取决于**它如何被调用**（无论它在哪里定义，甚至从哪里调用）。

`this`不是基于函数定义的函数的固定特性，而是每次调用函数时确定的动态特性。


```js
function classroom(teacher) {
    return function study() {
        console.log(
            `${ teacher } says to study ${ this.topic }`
        );
    };
}
var assignment = classroom("Kyle");
assignment();
// Kyle says to study undefined  -- 糟糕 :(
```

在**没有任何指定上下文的情况下**调用的上下文感知函数会默认将上下文设置为全局对象（在浏览器中是`window`）。

现在考虑：

```js
var homework = {
    topic: "JS",
    assignment: assignment
};

homework.assignment();
// Kyle says to study JS
```

最后：

```js
var otherHomework = {
    topic: "Math"
};

assignment.call(otherHomework);
// Kyle says to study Math
```

调用函数的第三种方式是使用`call(..)`方法，它接受一个对象（这里是`otherHomework`）来为函数调用设置`this`引用。属性引用`this.topic`解析为`"Math"`。



## 原型

把原型想象成两个对象之间的链接；这个链接隐藏在幕后，尽管有方法可以暴露和观察它。这个原型链接发生在对象创建时；它链接到另一个已经存在的对象。

考虑将一个对象定义为普通字面量：

```js
var homework = {
    topic: "JS"
};
```

`homework`对象只有一个属性：`topic`。然而，它的默认原型链接连接到`Object.prototype`对象，该对象上有常见的内置方法，如`toString()`和`valueOf()`等。

要定义对象原型链接，你可以使用`Object.create(..)`实用程序创建对象：

```js
var homework = {
    topic: "JS"
};

var otherHomework = Object.create(homework);

otherHomework.topic;   // "JS"
```

`Object.create(..)`的第一个参数指定了一个要链接新创建对象到的对象，然后返回新创建的（并已链接的！）对象。

## 作用域

JS是词法作用域（作用域相互嵌套，对于任何给定的表达式或语句，只有该作用域嵌套级别或更高/外部作用域的变量是可访问的；来自更低/内部作用域的变量是隐藏且不可访问的）的，尽管许多人声称它不是，因为它的模型中有两个在其他词法作用域语言中不存在的特定特性：

- 第一个通常被称为*变量提升hoisting*：在作用域中任何地方声明的所有变量都被视为在作用域的开头声明。
- 另一个是*函数提升*和 `var` 风格的*变量提升*是函数作用域的（如果没有，则附加到全局作用域），即使它们出现在代码块（Block，如 if/for）内部。

```js
// 变量提升
console.log(a); // 输出 undefined，而不是报错！
var a = 10;

// var 变量是函数作用域
function test() {
    if (true) {
        var x = 100; // x 写在 if 块里
    }
    
    // 在其他语言里，这里访问 x 应该报错
    // 但在 JS (var) 里，这里可以访问！
    console.log(x); // 输出 100
}
```

现代 JavaScript (ES6+) 引入了 `let` 和 `const`，这两个关键字完全支持**块级作用域**且**不发生提升**（存在暂时性死区 TDZ）。使用 let/const 后，JS 的行为就和其他主流词法作用域语言几乎完全一致了。
