## 全局作用域究竟在哪里？

全局作用域位于文件的最外层部分，即不在任何函数或其他块内部，这似乎是显而易见的。但事情并不那么简单。

不同的 JS 环境对你的程序作用域，特别是全局作用域的处理方式不同。JS 开发者在没有意识到的情况下怀有误解是很常见的。

从 ES2020 开始，JS 终于定义了一个标准化的全局作用域对象引用，称为 `globalThis`。所以，根据你的代码运行的 JS 引擎的新旧程度，你可以使用 `globalThis` 来代替所有其他方法。

我们甚至可以尝试定义一个在 `globalThis` 之前的 JS 环境中更安全的跨环境 polyfill，例如：

```js
const theGlobalScopeObject =
    (typeof globalThis != "undefined") ? globalThis :
    (typeof global != "undefined") ? global : // nodejs
    (typeof window != "undefined") ? window : // 浏览器
    (typeof self != "undefined") ? self :     // web worker
    (new Function("return this"))();
```

呼！这当然不理想，但如果你发现自己需要一个可靠的全局作用域引用，它确实能工作。

## 变量的生命周期

### TDZ

记住，我们到目前为止已经断言了几次，*编译器*最终会移除任何 `var`/`let`/`const` 声明符，用在每个作用域顶部注册相应标识符的指令来替换它们。

对于 `var` 声明，变量被“提升”到其作用域的顶部。但它也会自动初始化为 `undefined` 值，以便该变量可以在整个作用域中使用。

然而，`let` 和 `const` 声明在这方面并不完全相同。让我们来证明 `let` 和 `const` *确实*会提升（在作用域顶部自动注册），这要归功于我们的朋友遮蔽（参见第 3 章的“遮蔽”）：

```js
var studentName = "Kyle";

{
    console.log(studentName);
    // ???

    // ..

    let studentName = "Suzy";

    console.log(studentName);
    // Suzy
}
```

第一个 `console.log(..)` 语句会发生什么？如果 `let studentName` 没有提升到作用域的顶部，那么第一个 `console.log(..)` *应该*打印 `"Kyle"`，对吧？在那一刻，似乎只有外部的 `studentName` 存在，所以 `console.log(..)` 应该访问并打印那个变量。

但实际上，第一个 `console.log(..)` 抛出了一个 TDZ 错误，因为事实上，内部作用域的 `studentName` **确实**被提升了（在作用域的顶部自动注册）。**没有**发生（还没有！）的是那个内部 `studentName` 的自动初始化；它在那一刻仍然是未初始化的，因此违反了 TDZ！

总结一下，TDZ 错误发生是因为 `let`/`const` 声明*确实*将它们的声明提升到它们作用域的顶部，但是与 `var` 不同，它们将变量的自动初始化推迟到代码序列中原始声明出现的那一刻。这个时间窗口（提示：temporal），无论其长度如何，就是 TDZ。
