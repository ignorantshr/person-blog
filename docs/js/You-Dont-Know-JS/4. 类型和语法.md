## 空值

`null` 和 `undefined` 类型通常表示值的空缺或缺失。

对于很多 JS，尤其是开发人员编写的代码，这两个*空值*（nullish values）是可以互换的。

JS 提供了许多功能来帮助将这两个空值视为不可区分的。

例如，`==`（强制相等比较）运算符专门将 `null` 和 `undefined` 视为强制相等，但与语言中的其他任何值都不同。因此，如果你想检查一个值是否明确地是 `null` 或 `undefined`，执行 `.. == null` 检查是安全的：

```js
if (greeting == null) {
    // greeting is nullish/empty
}
```

另一个（最近）添加到 JS 的是 `??`（空值合并）运算符：

```js
who = myName ?? "User";

// 等同于：
who = (myName != null) ? myName : "User";
```

正如三元表达式等价物所示，`??` 检查 `myName` 是否为非空值，如果是，则返回其值。否则，它返回另一个操作数。

在某些情况下，`null` 和 `undefined` 会触发语言的不同行为，这一点很重要。我们不会在这里详尽地涵盖所有情况，但这里有一个例子：

```js
function greet(msg = "Hello") {
    console.log(msg);
}

greet();            // Hello
greet(undefined);   // Hello
greet("Hi");        // Hi

greet(null);        // null
```

参数上的 `= ..` 子句被称为“参数默认值”。只有在该位置的参数缺失，或者是确切的 `undefined` 值时，它才会生效并将其默认值分配给参数。如果你传递 `null`，该子句不会触发，因此 `null` 被分配给参数。
## 数字值

`number` 类型包含任何数值（整数或小数），例如 `-42` 或 `3.1415926`。这些值由 JS 引擎表示为 64 位、IEEE-754 双精度二进制浮点值。[^IEEE754]

JS `number` 总是小数；整数不会以不同的/特殊的方式存储。存储为 `number` 值的“整数”只是其小数部分没有任何非零部分；因此，`42` 在 JS 中与 `42.0` 和 `42.000000` 无法区分。

我们可以使用 `Number.isInteger(..)` 来确定一个 `number` 值是否有任何非零的小数部分：

```js
Number.isInteger(42);           // true
Number.isInteger(42.0);         // true
Number.isInteger(42.000000);    // true

Number.isInteger(42.0000001);   // false
```

强制转换可以显式地使用 `Number(..)` 函数（无 `new` 关键字）或在值前面使用一元 `+` 运算符来完成：

```js
someNumericText = "123.456";

Number(someNumericText);        // 123.456
+someNumericText;               // 123.456

Number("512px");                // NaN
+"512px";                       // NaN
```

默认情况下，JS 以标准十进制形式在输出/字符串中表示底层数值。然而，`number` 值有一个内置的 `toString(..)` 方法，可以生成任何指定基数/基数（与 `parseInt(..)` 一样，范围在 `2` - `36`）的字符串表示：

```js
myAge = 42;

myAge.toString(2);          // "101010"
myAge.toString(8);          // "52"
myAge.toString(16);         // "2a"
myAge.toString(23);         // "1j"
myAge.toString(36);         // "16"
```

你可以使用 `parseInt(..)` 将任何任意基数的字符串表示转换回 `number`，并使用适当的基数：

```js
myAge = 42;

parseInt(myAge.toString("23"),23);      // 42
```

### 安全整数限制

由于 `Number.MAX_VALUE` 是一个整数，你可能会假设它是语言中最大的整数。但这并不完全准确。

可以准确存储在 `number` 类型中的最大整数是 `2^53 - 1`，即 `9007199254740991`，它*远小于* `Number.MAX_VALUE`（大约 `2^1024 - 1`）。这个特殊的更安全的值被公开为 `Number.MAX_SAFE_INTEGER`：

```js
maxInt = Number.MAX_SAFE_INTEGER;

maxInt;             // 9007199254740991

maxInt + 1;         // 9007199254740992

maxInt + 2;         // 9007199254740992
```

我们已经看到，大于 `9007199254740991` 的整数可以出现。然而，这些更大的整数并不“安全”，因为当你对它们进行操作时，精度/准确性开始下降。如上所示，`maxInt + 1` 和 `maxInt + 2` 表达式都错误地给出了相同的结果，说明了超过 `Number.MAX_SAFE_INTEGER` 限制时的危险。

但是最小的安全整数是多少？

根据你如何解释“最小”，你可以回答 `0` 或者... `Number.MIN_SAFE_INTEGER`：

```js
Number.MIN_SAFE_INTEGER;    // -9007199254740991
```

JS 提供了一个工具来确定一个值是否是这个安全范围内的整数 (`-2^53 + 1` - `2^53 - 1`)：

```js
Number.isSafeInteger(2 ** 53);      // false
Number.isSafeInteger(2 ** 53 - 1);  // true
```

### 双零

你可能会惊讶地发现，JS 有两个零：`0` 和 `-0`（负零）。

这不仅仅是 JS 的一个有趣怪癖；它是由 IEEE-754[^IEEE754] 规范强制规定的。所有浮点数都是有符号的，包括零。尽管 JS 有点隐藏了 `-0` 的存在，但完全有可能产生它并检测到它：

```js
function isNegZero(v) {
    return v == 0 && (1 / v) == -Infinity;
}

regZero = 0 / 1;
negZero = 0 / -1;

regZero === negZero;        // true -- oops!
Object.is(-0,regZero);      // false -- phew!
Object.is(-0,negZero);      // true

isNegZero(regZero);         // false
isNegZero(negZero);         // true
```

你可能想知道我们为什么需要 `-0` 这样的东西。当使用数字来表示某个项目（如游戏角色或动画）的移动幅度（速度）以及其方向（例如，负数=左，正数=右）时，它可能很有用。

如果没有一个有符号的零值，你就无法判断这样一个物品在静止时指向哪个方向。

| 注意： |
| :--- |
| 虽然 JS 在 `number` 类型中定义了一个有符号的零，但在 `bigint` 数字类型中没有相应的有符号零。因此，`-0n` 仅被解释为 `0n`，两者无法区分。 |
## BigInteger 值

由于 JS `number` 中的最大安全整数是 `9007199254740991`（见上文），因此，JS 提供了备用的 `bigint` 类型（BigInteger），它可以存储任意大的（理论上没有限制，除了有限的机器内存和/或 JS 实现）整数。

为了区分 `bigint` 和一个整数 `number` 值，否则它们看起来会一样（`42`），JS 要求在 `bigint` 值上加一个 `n` 后缀：

```js
myAge = 42n;

inc = 1;

myAge += BigInt(inc);

myAge;              // 43n
```

## 数字行为

在数字相等性中有两个令人沮丧的例外（无论你使用 `==` 还是 `===`）：

```js
NaN === NaN;                // false -- ugh!
-0 === 0;                   // true -- ugh!
```

`NaN` 永远不等于它自己（即使使用 `===`），而 `-0` 总是等于 `0`（即使使用 `===`）。有时人们会惊讶于即使是 `===` 也有这两个例外。

然而，`Object.is(..)` 相等性检查没有这两个例外，因此对于与 `NaN` 和 `-0` 的相等性比较，请避免使用 `==` / `===` 运算符，而应使用 `Object.is(..)`——或者对于 `NaN` 特别地，使用 `Number.isNaN(..)`。
### 数字值方法

JS 语法的一个特殊细微之处在于，在处理数字字面量和属性/方法访问时，`.` 可能会有歧义。

如果一个 `.` 紧跟在一个数字字面量数字之后（没有空格），并且数字值中还没有 `.` 小数点，那么这个 `.` 就被假定为开始数字的小数部分。但是，如果 `.` 的位置明确*不是*数字字面量的一部分，那么它总是被视为属性访问。

```js
42 .toExponential(3);           // "4.200e+1"
```

在这里，空格消除了 `.` 的歧义，将其指定为属性/方法访问。使用 `(..)` 而不是空格来消除这种歧义可能更常见/更可取：

```js
(42).toExponential(3);          // "4.200e+1"
```

这个 JS 解析语法规则的一个不寻常的效果：

```js
42..toExponential(3);           // "4.200e+1"
```

所谓的“双点”习语，这个表达式中的第一个 `.` 是一个小数点，因此第二个 `.` 明确*不是*一个小数点，而是一个属性/方法访问。

`bigint` 类型的值不能有小数，所以解析是明确的，即字面量（带有尾随的 `n`）后面的 `.` 总是属性访问：

```js
42n.toString();                 // 42
```

# 第三章：对象值

## 对象类型

`object` 值类型包括几个子类型，每个子类型都有专门的行为，包括：

* 普通对象
* 基本对象（装箱原始值）
* 内置对象
* 数组
* 正则表达式
* 函数（又名“可调用对象”）

除了专门的行为之外，一个共同的特点是所有对象都可以作为持有值（包括函数/方法）的集合（属性的集合）。

### 普通对象

普通对象默认 `[[Prototype]]` 链接到 `Object.prototype`，使它们可以委托访问几个通用对象方法

## 基本对象

JS 定义了几个*基本*对象类型，它们是各种内置构造函数的实例，包括：

* `new String()`
* `new Number()`
* `new Boolean()`
### 自动对象

我多次提到*自动装箱*（包括第一章和第二章，以及本章到目前为止的几次）。现在终于到了我们解释这个概念的时候了。

在值上访问属性或方法要求该值是一个对象。正如我们在第一章中已经看到的，原始值*不是*对象，所以 JS 需要临时将这样的原始值转换/包装成其基本对象对应物[^AutoBoxing]以执行该访问。

当原始值被*自动装箱*为其基本对象对应物时，那些内部创建的对象可以通过 `[[Prototype]]` 链接到它们各自基本对象的原型，从而访问预定义的属性/方法（如 `length` 和 `toUpperCase()`）。

由于 `null` 和 `undefined` 没有对应的基本对象，所以不存在对这些值的*自动装箱*。
