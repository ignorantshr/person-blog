## 对象

### 属性名

对象字面量中的属性名几乎总是被视为/强制转换为**字符串**值。一个*例外*是整数（或“看起来像整数”）的属性“名”：

```js
anotherObj = {
    42:       "<-- 这个属性名将被视为整数",
    "41":     "<-- ...这个也是",

    true:     "<-- 这个属性名将被视为字符串",
    [myObj]:  "<-- ...这个也是"
};
```

而`myObj`标识符引用，通过周围的`[ .. ]`*计算*（注意，这并不是一个数组），将把对象的值强制转换为一个字符串（通常是默认的`"[object Object]"`）。

```js
anotherObj = {
    ["x" + (21 * 2)]: true
};
```

表达式`"x" + (21 * 2)`必须出现在`[ .. ]`括号内，它会立即被计算，结果(`"x42"`)被用作属性名。

**如果你需要实际使用一个对象作为键/属性名，永远不要依赖这种计算出的字符串强制转换**。相反，使用一个更专门的数据结构，称为`Map`（在ES6中添加），其中用作属性“名”的对象保持原样，而不会被强制转换成字符串值。

### 简洁方法

虽然不特别常见，但简洁的方法/生成器甚至可以有带引号或计算出的名称：

```js
anotherObj = {
    "greet-4"() { console.log("你好，观众！"); },

    // 简洁计算名称
    [ "gr" + "eet 5" ]() { console.log("你好，观众！"); },

    // 简洁计算生成器名称
    *[ "ok, greet 6".toUpperCase() ]() { yield "你好，观众！"; }
};
```

### 对象展开

当在对象字面量内部使用`...`时，它会将另一个对象值的内容（属性，即键/值对）“展开”到正在定义的对象中：

```js
anotherObj = {
    favoriteNumber: 12,

    ...myObj,   // 对象展开，浅拷贝`myObj`

    greeting: "你好！"
}
```

`myObj`属性的展开是浅层的，因为它只复制`myObj`的顶层属性；这些属性持有的任何值都只是被赋值过去。如果这些值中有任何是对其他对象的引用，那么引用本身会被赋值（通过复制），但底层的对象值*不会*被复制——所以你最终会得到多个对同一个对象的共享引用。

请记住，你不能将`...`展开到一个现有的对象值中；`...`对象展开语法只能出现在`{ .. }`对象字面量内部，它正在创建一个新的对象值。要执行类似的浅对象复制，但使用API而不是语法，请参见本章后面的“对象条目”部分（其中涵盖了`Object.entries(..)`和`Object.fromEntries(..)`）。

但是，如果你想将对象属性（浅层地）复制到一个*现有*的对象中，请参见本章后面的“分配属性”部分（其中涵盖了`Object.assign(..)`）。

### 深对象拷贝

此外，由于`...`不做完整的深层对象复制，对象展开通常只适用于复制仅包含简单原始值的对象，而不是对其他对象的引用。

深层对象复制是一个极其复杂和细致的操作。复制像`42`这样的值是显而易见和直接的，但是复制一个函数（它是一种特殊的对象，也通过引用持有），或者复制一个外部（不完全在JS中）对象引用，比如一个DOM元素，意味着什么呢？如果一个对象有循环引用（比如一个嵌套的后代对象持有一个指向上层祖先对象的引用）会发生什么？关于如何处理所有这些边缘情况，外界有各种各样的意见，因此对于深层对象复制没有单一的标准。

对于深层对象复制，标准方法一直是：

1.  使用一个库实用程序，它声明了关于如何处理复制行为/细微差别的特定观点。
2.  使用`JSON.parse(JSON.stringify(..))`往返技巧——这只有在没有循环引用，并且对象中没有不能用JSON正确序列化的值（例如函数）时才能正确“工作”。

不过，最近出现了第三种选择。这不是一个JS特性，而是由Web平台等环境提供给JS的一个配套API。现在可以使用`structuredClone(..)`[^structuredClone]对对象进行深层复制。

```js
myObjCopy = structuredClone(myObj);
```

这个内置实用程序背后的底层算法支持复制循环引用，以及比`JSON`往返技巧**更多**类型的值。然而，这个算法仍然有其局限性，包括不支持克隆函数或DOM元素。

### 访问属性

现有对象的属性访问最好使用`.`运算符。与对象字面量类似，要访问的属性名可以通过`[ .. ]`括号计算得出。

实际上，你放在`[ .. ]`括号之间的可以是任何任意的JS表达式。JS会首先对表达式求值，然后将结果值用作要在对象上查找的属性名：

```js
function howMany(x) {
    return x + 1;
}

myObj[`${ howMany(1) } nicknames`];
```

### 解构

```js
myObj = {
    favoriteNumber: 42,
    isDeveloper: true,
    firstName: "Kyle"
};

const { favoriteNumber = 12 } = myObj;
const {
    isDeveloper: isDev,
    firstName: firstName,
    lastName: lname = "--missing--"
} = myObj;

favoriteNumber;   // 42
isDev;            // true
firstName;        // "Kyle"
lname;            // "--missing--"
```

`lastName: lname = "--missing--"`结合了源-目标重命名和默认值（如果`lastName`源属性缺失或为`undefined`）。

上面的代码片段将对象解构与变量声明结合在一起——在这个例子中，使用了`const`，但`var`和`let`也同样有效——但这本身并不是一个声明机制。解构是关于访问和赋值（从源到目标），所以它可以对**现有的目标**进行操作，而不是声明新的目标：

```js
let fave;

// 当不使用声明符时，
// 这里的( )是必需的语法
({ favoriteNumber: fave } = myObj);

fave;  // 42
```

### 条件属性访问

`A?.B`。

此运算符将检查左侧引用（`A`）以查看其是否为nullish（`null`或`undefined`）。如果是，则属性访问表达式的其余部分将被短路（跳过），并返回`undefined`作为结果（即使实际遇到的是`null`！）。否则，`?.`将像普通的`.`运算符一样访问该属性。

| 警告：                                                       |
| :----------------------------------------------------------- |
| 这个特性还有第三种形式，名为“可选调用”，它使用`?.(`作为运算符。它用于在执行属性中的函数值之前对属性执行非nullish检查。例如，可以用`myObj.someFunc?.(42)`代替`myObj.someFunc(42)`。`?.(`会在调用它（用`(42)`部分）之前检查以确保`myObj.someFunc`不是nullish。虽然这听起来像一个有用的特性，但我认为这足够危险，以至于需要完全避免这种形式/构造。<br><br>我的担忧是，`?.(`似乎让我们确保函数在调用它之前是“可调用的”，而实际上我们只是在检查它是否不是nullish。与`?.`不同，`?.`可以允许对一个非nullish但也不是对象的值进行“安全”的`.`访问，`?.(`的非nullish检查并非同样“安全”。如果所讨论的属性中包含任何非nullish、非函数的值，比如`true`或`"Hello"`，那么`(42)`调用部分将被调用，但会抛出一个JS异常。所以换句话说，这种形式不幸地伪装得比它实际上更“安全”，因此基本上在所有情况下都应该避免使用。如果一个属性值可能*不是*一个函数，那么在尝试调用它之前，请对其进行更全面的函数性检查。不要假装`?.(`在为你做这件事，否则你代码的未来读者/维护者（包括未来的你！）很可能会后悔。 |

### 访问非对象上的属性

这听起来可能违反直觉，但你通常可以从本身不是对象的值中访问属性/方法：

```js
fave = 42;

fave;              // 42
fave.toString();   // "42"
```

如果你对一个非对象、非nullish的值执行属性访问（`.`或`[ .. ]`），JS默认会（暂时地！）将该值强制转换为一个对象包装的表示形式，从而允许对该隐式实例化的对象进行属性访问。

这个过程通常被称为“装箱”。

因此，在上面的代码片段中，就在对`42`这个值进行`.toString`访问的那一刻，JS会将这个值装箱成一个`Number`对象，然后执行属性访问。

请注意，`null`和`undefined`可以通过调用`Object(null)` / `Object(undefined)`进行对象化。然而，JS不会自动对这些空值进行装箱，因此对它们的属性访问将会失败（如前文“条件属性访问”一节所述）。

### 赋值属性

可以一次性为一个或多个属性赋值——假设源属性（名称和值对）在另一个对象中——使用`Object.assign(..)`（ES6中添加）方法：

```js
// 浅拷贝`myObj`中所有（自有且可枚举的）属性到`anotherObj`
Object.assign(anotherObj,myObj);

Object.assign(
    /*target=*/anotherObj,
    /*source1=*/{
        someProp: "some value",
        anotherProp: 1001,
    },
    /*source2=*/{
        yetAnotherProp: false
    }
);
```

`Object.assign(..)`将第一个对象作为目标，第二个（以及可选的后续）对象作为源。复制的方式与前面“对象展开”部分描述的方式相同。

### 删除属性

一旦一个属性在对象上被定义，唯一的移除方法是使用`delete`运算符：

```js
anotherObj = {
    counter: 123
};

anotherObj.counter;   // 123

delete anotherObj.counter;

anotherObj.counter;   // undefined
```

与普遍的误解相反，JS的`delete`运算符并**不**直接通过垃圾回收（GC）进行任何内存的释放/回收。它唯一做的事情就是从一个对象中移除一个属性。

从对象中删除属性与为其赋`undefined`或`null`这样的值是**不同**的。一个被赋为`undefined`的属性，无论是初始赋值还是后续赋值，仍然存在于对象上，并且在枚举内容时可能仍然会被显示出来。

### 更好的存在性检查

ES2022 已经确定了一个新特性，`Object.hasOwn(..)`。它做的事情与`hasOwnProperty(..)`基本相同，但它是作为对象值外部的静态辅助函数调用的，而不是通过对象的`[[Prototype]]`调用，这使得它在使用上更安全、更一致：

```js
// 而不是：
myObj.hasOwnProperty("favoriteNumber")

// 我们现在应该更喜欢：
Object.hasOwn(myObj,"favoriteNumber")
```

## 对象子类型

JS中有各种专门的对象子类型。但到目前为止，你将与之交互的两种最常见的是数组和`function`。

| 注意：                                                       |
| :----------------------------------------------------------- |
| 所谓“子类型”，我们指的是从父类型继承了行为然后特化或扩展了这些行为的派生类型的概念。换句话说，这些子类型的值完全是对象，但它们也*不仅仅是*对象。 |

### 数组

数组是专门用于**数字索引**的对象，而不是使用字符串命名的属性位置。它们仍然是对象，所以像`favoriteNumber`这样的命名属性是合法的。但是强烈不建议在数字索引的数组中混合使用命名属性。

回想一下，对象上任何“看起来像”整数的字符串属性名——能够被有效地强制转换为一个数字整数——实际上都会被当作一个整数属性（即整数索引）。数组也是如此。你应该总是使用`42`作为整数索引（即属性名），但如果你使用字符串`"42"`，JS会假设你指的是一个整数并为你这样做。

```js
// "2"在这里作为整数索引工作，但不建议这样做
myList["2"];    // 109
```

“数组上没有命名属性”*规则*的一个例外是，所有数组都会自动公开一个`length`属性，该属性会自动保持更新为数组的“长度”。

#### 空槽

JS数组的设计中还有一个非常不幸的“缺陷”，被称为“空槽”。如果你给一个数组的索引赋值，该索引超出了数组当前末尾一个以上的位置，JS会把中间的槽位留为“空”，而不是像你可能期望的那样自动将它们赋值为`undefined`：

```js
myList = [ 23, 42, 109 ];
myList.length;              // 3

myList[14] = "Hello";
myList.length;              // 15

myList;                     // [ 23, 42, 109, empty x 11, "Hello" ]

// 看起来像一个带有真实`undefined`值的真实槽位，
// 但要小心，这是一个陷阱！
myList[9];                  // undefined
```

你可能会想知道为什么空槽这么糟糕？一个原因是：JS中有一些API，比如数组的`map(..)`，会令人惊讶地跳过空槽！

### 函数

函数也是子对象类型。这意味着除了可执行之外，它们还可以添加或访问命名属性，但你应该避免在函数对象上赋值属性。

函数有两个你可能会发现自己与之交互的预定义属性，特别是出于元编程的目的：

```js
function help(opt1,opt2,...remainingOpts) {
    // ..
}

help.name;          // "help"
help.length;        // 2
```

函数的`length`是其显式定义的参数的数量，直到但不包括具有默认值定义的参数（例如，`param = 42`）或“剩余参数”（例如，`...remainingOpts`）。

## 对象特性

除了为特定属性定义行为之外，某些行为还可以在整个对象范围内进行配置：

*   可扩展
*   密封
*   冻结

### 可扩展性

可扩展性指的是一个对象是否可以被定义/添加新的属性。默认情况下，所有对象都是可扩展的，但是你可以关闭一个对象的可扩展性，但其对象类型的原型依然可以添加新的属性：

```js
myObj = {
    favoriteNumber: 42
};

myObj.firstName = "Kyle";                  // 正常工作

Object.preventExtensions(myObj);

myObj.nicknames = [ "getify", "ydkjs" ];   // 失败
myObj.favoriteNumber = 123;                // 正常工作
```

注意，一般来说，不可扩展对象的属性仍然可以被*删除*。

### 密封

密封一个对象会[阻止其扩展](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Object/preventExtensions)并且使得现有属性不可配置。密封对象有一组固定的属性：不能添加新属性、不能删除现有属性或更改其可枚举性和可配置性、不能重新分配其原型。只要现有属性的值是可写的，它们仍然可以更改。

```js
const obj = {
  prop() {},
  foo: "bar",
};

// 可以添加新属性，可以更改或删除现有属性。
obj.foo = "baz";
obj.lumpy = "woof";
delete obj.prop;

const o = Object.seal(obj);

o === obj; // true
Object.isSealed(obj); // true

// 更改密封对象的属性值仍然有效。
obj.foo = "quux";

// 但不能将数据属性转换成访问者属性，反之亦然。
Object.defineProperty(obj, "foo", {
  get() {
    return "g";
  },
}); // 抛出 TypeError

// 现在，除了属性值之外的任何更改都将失败。
obj.quaxxor = "the friendly duck";
// 静默不添加属性
delete obj.foo;
// 静默不添删除属性

// ...且严格模式下，这种尝试将会抛出 TypeError。
function fail() {
  "use strict";
  delete obj.foo; // 抛出一个 TypeError
  obj.sparky = "arf"; // 抛出一个 TypeError
}
fail();

// 尝试通过 Object.defineProperty 添加属性也会抛出错误。
Object.defineProperty(obj, "ohai", {
  value: 17,
}); // 抛出 TypeError
Object.defineProperty(obj, "foo", {
  value: "eit",
}); // 更改现有属性值
```

### 冻结

冻结对象可以[防止扩展](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Object/preventExtensions)，并使现有的属性不可写入和不可配置。被冻结的对象不能再被更改：不能添加新的属性，不能移除现有的属性，不能更改它们的可枚举性、可配置性、可写性或值，对象的原型也不能被重新指定。冻结一个对象是最高完整性级别的保护措施。

请注意，对象类型的值仍然可以修改，除非它们也被冻结。数组作为一种对象也可以被冻结；数组被冻结后，既不能更改它的元素，也不能向数组中添加或删除元素。

## 保持`class`y

在`class`块内部，即使文件中或其函数中没有`"use strict"` pragma，所有代码也以严格模式运行。特别是，这会影响函数调用的`this`行为，如第4章所述。

### 构造函数

所有类都有一个特殊的方法，称为“构造函数”。如果省略，定义中会假定一个默认的空构造函数。

每当创建类的`new`实例时，都会调用构造函数：

```js
class Point2d {
    constructor() {
        console.log("这是你的新实例！");
    }
}

var point = new Point2d();
// 这是你的新实例！
```

尽管语法上暗示存在一个实际名为`constructor`的函数，但JS定义了一个指定的函数，但其名称为类名（上面为`Point2d`）：

```js
typeof Point2d;       // "function"
```

不过，它不*仅仅*是一个常规函数；这种特殊类型的函数行为略有不同：

```js
Point2d.toString();
// class Point2d {
//   ..
// }

Point2d();
// TypeError: Class constructor Point2d cannot
// be invoked without 'new'

Point2d.call({});
// TypeError: Class constructor Point2d cannot
// be invoked without 'new'
```

## 类实例 `this`

我们将在后续章节中更详细地介绍`this`关键字。但就面向类的代码而言，`this`关键字通常指的是任何方法调用的上下文——**当前实例**。

### super

如果你想从子类访问一个继承的方法，即使它已经被覆盖，你可以使用`super`而不是`this`：

```js
class Point2d {
    x = 3
    y = 4

    getX() {
        return this.x;
    }
}

class Point3d extends Point2d {
    x = 21
    y = 10
    z = 5

    getX() {
        return this.x * 2;
    }
    printX() {
        console.log(`x: ${super.getX()}`);
    }
}

var point = new Point3d();

point.printX();       // x: 21
```

注意 x 的输出！

## this

关于 `this` 建议阅读原文，下面的内容仅是简单的笔记。

在本章的其余部分，请不断提醒自己：函数的`this`值是由**如何**调用该函数决定的。

这意味着你不能看函数的定义，也不能看函数定义的位置（甚至不能看它所在的`class`！）。实际上，甚至函数从哪里调用都无关紧要。

我们只需要看**如何**调用函数；这是唯一重要的因素。

### `new`上下文调用

你通常看到`new`与`class`一起用于创建实例。但作为JS语言的底层机制，`new`本质上不是一个`class`操作。

在某种意义上，`new`关键字劫持了一个函数，并将其行为强制转换为与正常调用不同的模式。以下是当一个函数用`new`调用时，JS执行的4个特殊步骤：

1.  凭空创建一个全新的空对象。
2.  将该新空对象的`[[Prototype]]`链接到函数的`.prototype`对象（参见第二章）。
3.  以`this`上下文设置为该新空对象来调用该函数。
4.  如果函数没有显式地返回自己的对象值（用`return ..`语句），则假定函数调用应该返回新的对象（来自步骤1-3）。

### 上下文赋值的四条规则

我们已经看到了函数调用中`this`上下文赋值的四条规则。让我们按优先顺序列出它们：

1.  函数是否用`new`调用，创建并设置一个新的`this`？
2.  函数是否用`call(..)`或`apply(..)`调用，*显式*设置`this`？
3.  函数是否在调用点用一个对象引用调用（例如，`point.init(..)`），*隐式*设置`this`？
4.  如果以上都不是……我们是否处于非严格模式？如果是，*默认*将`this`设置为`globalThis`。但如果在严格模式下，*默认*将`this`设置为`undefined`。

这些规则，基于一个巨大的假设：你正在处理一个*常规*函数（或方法）。

*按此顺序*，是JS如何确定函数调用的`this`。如果多个规则匹配一个调用点（例如，`new point.init.call(..)`），列表中第一个匹配的规则获胜。

### 找不到调用点？

很多框架，除非查看其源码，否则难以找到 this 的调用点。

词法`this`，意思是`this`的行为像一个词法作用域变量，而不是像一个动态上下文绑定。

箭头函数不一样。在`=>`函数中，`this`关键字……**不是关键字**。它与任何其他变量，如`context`或`happyFace`或`foobarbaz`，绝对没有区别。

重要的是我们考虑*哪个*调用点，而不仅仅是当前调用堆栈中的*任何*调用点。重要的调用点是，当前调用堆栈中***实际分配`this`上下文***的最近的函数调用。

由于`=>`箭头函数永远没有一个`this`-赋值的调用点（无论如何），所以那个调用点与问题无关。我们必须不断地向上追溯调用栈，直到找到一个*是*`this`-赋值的函数调用——即使被调用的函数本身不是`this`-感知的。

**那**是唯一重要的调用点。

考验：

```js
globalThis.value = { result: "Sad face" };

function one() {
    function two() {
        var three = {
            value: { result: "Hmmm" },

            fn: () => {
                const four = () => this.value;
                return four.call({
                    value: { result: "OK", },
                });
            },
        };
        return three.fn();
    };
    return two();
}

new one();          // ???
```

`=>`函数不能与`new`关键字一起使用。在概念上和实际上，`=>`箭头函数不是一个带有硬绑定`this`的函数，它是一个根本没有`this`的函数。因此，`new`对这样的函数没有意义，所以JS就禁止了它。

# 委托

## 构造函数到底是什么？

在第三章中，我们看到`constructor(..)`是`class`实例构造的主要入口点。但`constructor(..)`实际上不做任何*创建*工作，它只做*初始化*工作。换句话说，当`constructor(..)`运行并初始化实例时——例如，`this.whatever`类型的赋值——实例已经被创建了。

## Prototype[gemini]

这是 JavaScript 原型链中最容易混淆的三个概念。要彻底搞懂它们，我们需要从**“谁拥有它”**以及**“它的作用是什么”**这两个维度来区分。

用一句话总结它们的关系：
**`__proto__` 是访问内部属性 `[[Prototype]]` 的一种历史手段，而 `prototype` 是函数特有的属性，用来在创建实例时设置实例的 `[[Prototype]]`。**

### 1. `[[Prototype]]` —— 真正的“原型”

*   **本质**：这是对象内部的一个**隐藏属性**（Internal Slot）。
*   **作用**：它决定了对象继承了谁。当你在一个对象上查找属性时，如果找不到，JS 引擎就会去 `[[Prototype]]` 指向的对象里找。这就是“原型链”的物理连接。
*   **可见性**：你是无法直接在代码中写 `obj.[[Prototype]]` 来访问它的，这是 JS 引擎内部的实现细节。

> **比喻**：它是你的**DNA**。它决定了你的基因来自哪里，藏在你身体内部，不能直接拿出来看。

---

### 2. `prototype` —— 函数的“模具”

*   **本质**：这是一个**普通属性**，**只有函数（构造函数/类）才拥有**。普通对象（如 `{a:1}`）是没有这个属性的。
*   **作用**：它是一个“预备役”。当你使用 `new` 关键字调用这个函数来创建一个新对象时，新对象的 `[[Prototype]]` 就会被指向这个函数的 `prototype` 属性。
*   **注意**：`Function.prototype` 并不是该函数自己的原型，而是它创建的**实例的原型**。

> **比喻**：这是工厂里的**模具**。模具本身不是零件，但用这个模具造出来的零件（实例），形状都跟模具一样。

---

### 3. `__proto__` —— 历史遗留的“访问器”

*   **本质**：这是一个**访问器属性**（Getter/Setter），暴露在 `Object.prototype` 上。
*   **作用**：因为 `[[Prototype]]` 是隐藏的，早期浏览器（如 Chrome, Firefox）私自添加了 `__proto__` 属性，让开发者可以读取或修改对象的 `[[Prototype]]`。后来 ES6 为了兼容性被迫将其标准化，但**不推荐使用**。
*   **等价关系**：`obj.__proto__` 等同于读取 `obj` 的 `[[Prototype]]`。

> **比喻**：这是为了看 DNA 而走的**后门**或者**显微镜**。官方现在推荐用正规的医疗设备（`Object.getPrototypeOf`）来看，不要用这个土法子了。

---

### 4. 三者关系图解与代码验证

这也是面试中最核心的公式：
**`实例.__proto__ === 构造函数.prototype`**

```javascript
// 1. 定义一个构造函数（它是制造机器）
function Dog(name) {
    this.name = name;
}

// 2. Dog 有 prototype 属性（这是模具）
Dog.prototype.bark = function() {
    console.log('汪汪');
};

// 3. 使用 new 创建实例
const myDog = new Dog('旺财');

// --- 验证关系 ---

// Q1: myDog 的真实原型是谁？
// A: 是 Dog.prototype
console.log(myDog.__proto__ === Dog.prototype); // true

// Q2: Dog.prototype 也是个对象，它的原型是谁？
// A: 是 Object.prototype (因为它是普通对象)
console.log(Dog.prototype.__proto__ === Object.prototype); // true

// Q3: Dog 本身是个函数，它的原型是谁？
// A: 是 Function.prototype (所有函数都是 Function 的实例)
console.log(Dog.__proto__ === Function.prototype); // true
```
